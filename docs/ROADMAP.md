# План развития KinoPub Improve

Живой документ: приоритеты могут меняться.  
Статус на момент `0.0.1.0`: фильмы + скан списков + sync в MyShows в рабочем виде.

---

## Сейчас (база)

Уже есть и считается готовым к использованию:

- скан / затемнение / скрытие просмотренного на списках и поиске
- кэш, экспорт / импорт / сброс
- основной URL + зеркала
- sync фильмов в MyShows (dry-run, отмена, resume, отчёт, ambiguous)
- options, side panel, badge, компактный popup
- unit-тесты на матчинг / hosts

---

## P0 — следующий крупный функционал

### 1. Синхронизация сериалов
Самый ожидаемый пробел в продукте.

- [ ] Сбор просмотренных сериалов / сезонов / эпизодов с Kinopub
- [ ] Маппинг на MyShows (show + season/episode API)
- [ ] Правила: что считать «готово» (весь сезон / весь сериал / только отмеченные эпизоды)
- [ ] Dry-run и отчёт по сериалам (отдельные reason-коды)
- [ ] Включить пункты UI «Сериалы» / «Фильмы и сериалы»

### 2. Надёжность sync под нагрузкой
- [ ] Более устойчивый resume при долгих прогонах (тысячи title)
- [ ] Явный «сбросить залипший sync» в UI, если SW убит
- [ ] Лимиты / паузы с адаптацией при 429
- [ ] Метрики в отчёте: время, RPC count, origin

---

## P1 — качество матчинга и данных

### 3. Умнее матч фильмов
- [ ] Расширить покрытие внешних ID (если MyShows/каталог отдают больше полей)
- [ ] Лучше обрабатывать remake / одинаковые названия разных лет
- [ ] Подсказки в отчёте: почему выбран кандидат (KP / IMDb / title+year)
- [ ] Опция «не писать в MyShows без KP/IMDb», если ID есть на Kinopub

### 4. Кэш просмотренного
- [ ] Настраиваемый TTL для `watched` (сейчас фиксированные 7 дней)
- [ ] Кнопка «перепроверить видимое на странице» без полного сброса кэша
- [ ] Статистика кэша в popup/options (кол-во watched / unwatched)

### 5. Источник «История»
- [ ] Ещё жёстче фильтровать мусорные `/item/view/` со страниц history
- [ ] Опция «только фильмы» / «только сериалы» на этапе сбора ID
- [ ] Прогресс по страницам history в badge / отчёте

### 6. Chrome Web Store (или GitHub Releases)

## P3 — инженерия

### 9. Тесты и качество
- [ ] Фикстуры реальных HTML item / history / search (анонимизированные)
- [ ] Тесты на сбор ID из history (card-scoped)
- [ ] Тесты на «залипший running» / finalize stuck sync
- [ ] CI: `npm test` + `npm run typecheck` на PR

### 10. Архитектура
- [ ] Постепенный TypeScript (`lib/` → background → UI), без big-bang
- [ ] Общий модульный бандл вместо голых `importScripts` (esbuild), если разрастётся
- [ ] Разделить myshows-sync на collect / match / write / report

### 11. Производительность скана
- [ ] Ещё легче probe HTML (меньше DOMParser на горячем пути)
- [ ] Приоритет карточкам в viewport
- [ ] Опциональный idle-скан только на активной вкладке

## Идеи «когда-нибудь» (не коммитим сроки)

- Синк обратный: MyShows → пометки на Kinopub (осторожно с правами/этикой)
- Списки/коллекции Kinopub как источник sync
- Telegram/webhook «sync закончился»
- Поддержка других трекеров (кроме MyShows)
- Firefox (MV3 отличия)

---

## Что сознательно не делаем

- Хранение паролей Kinopub / MyShows в расширении (только cookies сессии пользователя)
- Автологин / обход антибота
- Массовый «накруточный» sync без dry-run по умолчанию в доках

---

## Предлагаемый порядок релизов

| Версия | Фокус |
|--------|--------|
| `0.0.2` | сериалы (MVP: хотя бы seasons allWatched → finished show/season) |
| `0.0.3` | отчёт/матчинг/TTL watched в options + CI |
| `0.1.0` | стабильный sync фильмы+сериалы, GitHub Release / подготовка к Store |

Мелкие фиксы и UX можно выпускать минорными патчами (`0.0.1.x`) между крупными пунктами.
